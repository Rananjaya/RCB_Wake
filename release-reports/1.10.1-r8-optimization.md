## Optimization comparison

Compared with the local 1.10.0 production artifacts:

| Measure | 1.10.0 | 1.10.1 | Change |
|---|---:|---:|---:|
| APK | 55,324,878 bytes | 49,884,309 bytes | 9.83% smaller |
| AAB | 37,204,793 bytes | 34,569,793 bytes | 7.08% smaller |
| APK DEX payload | 17,591,960 bytes in 2 DEX files | 3,636,220 bytes in 1 DEX file | 79.33% smaller |

R8's `mapping.txt` contains 95 surviving app-package class mappings; 78 names changed
(`com.rcb.wake.alarm.AlarmController` becomes `x2`, for example). This is an estimate of class-name
obfuscation in the app namespace, using mapped surviving classes as the denominator. It is **not**
Google Play's obfuscation score and does not prove that Play's 25% threshold is met. Play Console
must confirm that score after upload.

R8 retained manifest component class names, and the React Native module bridge methods such as
`dismissSession` and `getAlarms` remain named. `resources.txt` reports the Siren 2 raw resource as
reachable; the optimized resource table resolves it to `res/L3.wav`.

## Validation and tests

- `./gradlew :app:assembleRelease :app:bundleRelease`: passed; build executed
  `minifyReleaseWithR8`, `convertShrunkResourcesToBinaryRelease`, and
  `optimizeReleaseResources`.
- `npm test -- --runInBand`: 13 suites, 80 tests passed.
- `npm run typecheck`: passed.
- `./gradlew :app:testDebugUnitTest`: 72 tests passed. This project does not expose a
  `testReleaseUnitTest` Gradle task, and has no `src/androidTest` integration-test source set.
- `bundletool validate`: passed. `bundletool dump config` reports `PAGE_ALIGNMENT_16K`.
- `zipalign -c -P 16 -v 4`: passed for the APK.
- ELF inspection: all 36 packaged `.so` files (74 `LOAD` segments across arm64-v8a and x86_64)
  have 16 KiB (`0x4000`) or greater segment alignment.
- APK v2 signature verification and AAB JAR signature verification: passed. Both new artifacts
  match the prior production signing certificate.
- The exact signed 1.10.1 production APK was installed on a Pixel 8 Android 15/API 35 emulator.
  It was installed over the archived signed 1.10.0 APK using `adb install -r`; the existing
  daily alarm, Pink Dream theme, 24-hour clock, and Chinese language setting survived the upgrade.
- React Native/Hermes launched and rendered the alarm list after upgrade and reboot. Alarm list,
  settings, and localized labels rendered with no fatal app/JS exception in the checked log window.
- Alarm scheduling and exact alarm delivery passed. A one-time Siren 2 alarm fired with the screen
  locked; `RingingActivity` appeared over the lock screen and the `alarm_ringing` notification was
  posted. Siren 2 preview played from the app.
- Dismissal passed: the ring activity closed and its active ring notification was removed.
- Snooze passed: the five-minute snooze action dismissed the ring, posted the `alarm_status`
  snooze notification with a stop action, and scheduled `ALARM_FIRE` five minutes later. That
  snoozed alarm rang again and could be dismissed.
- Reboot recovery passed: after emulator reboot, the persisted 20:00 alarm was re-registered by
  the app's boot recovery path and rang at 20:00. The manifest receiver remained registered.
- Timer passed: a one-minute timer reached its completion screen and posted the `timer_done`
  notification with actions.
- Widget registration passed: Android's widget service lists both
  `ClockWidgetProvider` and `GlanceWidgetProvider` from the optimized install. A widget was not
  placed on the launcher, so rendered widget appearance/actions remain unverified.
- Notification checks passed for the alarm ring, snooze status, and timer completion channels.
- Weather remains off by default. Opening the opt-in flow showed that a city must be selected;
  the emulator reported no network, so geocoding/provider fetch and rendered forecast were not
  verified. No city or location was submitted.
- NFC and Xiaomi/Redmi HyperOS behavior are hardware/vendor-specific and were not verified on the
  Pixel emulator. QR/camera challenge, math challenge, stopwatch, Pomodoro, world clock, and
  bedtime features were not exercised in this emulator session.
- Emulator testing changed no source or build configuration and did not rebuild artifacts. The
  APK/AAB SHA-256 values above were rechecked after testing and remain unchanged. Mapping file
  SHA-256: `7196519739bf7ba275ada119376a453013f6d89b9344928d19e6383b13354368`.
- No physical device was used; this is not a blocker under the approved emulator-only scope.
- APK and AAB signatures were checked on the final archive copies; both match the original tested
  artifact signatures. `SHA256SUMS.txt` was verified against those files.
