# Architecture decision records

Short records of the decisions that shape RCB Wake. Status is *Accepted* unless noted.

### ADR-001 · React Native 0.88.1 with the New Architecture
The development machine already built React Native 0.88.1 projects successfully and had its
artifacts cached; all chosen libraries declare support for it. Bridgeless mode and TurboModules
are enabled. Dependencies are pinned to exact or narrow ranges.

### ADR-002 · Kotlin owns persistence; JavaScript is a view
To avoid two conflicting sources of truth, and because alarms must ring without JavaScript, all
data lives in one SQLite database and SharedPreferences managed by Kotlin. JS reads and writes only
through the TurboModule and re-reads after engine events. The spec suggested a JS SQLite library;
using Android's built-in `SQLiteOpenHelper` meets the "SQLite" requirement with no extra
dependency.

### ADR-003 · SharedPreferences instead of MMKV
The native ringing screen, notifications and widget need theme, language and format without
JavaScript. Native SharedPreferences serve both sides; MMKV would add a Nitro dependency without
benefit.

### ADR-004 · `setAlarmClock()` for alarms
Exact, Doze-exempt, shows the system next-alarm indicator, and allows starting the ringing
foreground service from the background. Each occurrence is scheduled individually.

### ADR-005 · `USE_EXACT_ALARM` with `SCHEDULE_EXACT_ALARM` capped at API 32
Google Play allows `USE_EXACT_ALARM` for apps whose core function is an alarm clock. It does not
exist before Android 13, so `SCHEDULE_EXACT_ALARM` is declared with `maxSdkVersion="32"` for
Android 12/12L only. Neither is requested indiscriminately on the same API level.

### ADR-006 · Monotonic clock for timers, Pomodoro and stopwatch
`ELAPSED_REALTIME_WAKEUP` and `SystemClock.elapsedRealtime()` are immune to manual clock and
time-zone changes. Wall-clock end times are stored only to recover after a reboot.

### ADR-007 · Device-protected storage and Direct Boot
After a reboot the device may stay locked overnight. Making storage, receivers, the ringing
service and activity Direct Boot aware lets alarms be restored at `LOCKED_BOOT_COMPLETED`.

### ADR-008 · One ringing session
Simultaneous alarms join a single session with one sound and one dismissal, avoiding overlapping
audio and competing screens.

### ADR-009 · `mediaPlayback` foreground service type
Alarm audio is media playback; this type has no time limit and is permitted when started from an
exact-alarm broadcast.

### ADR-010 · Math challenge in React Native, audio in Kotlin
The challenge UI uses React Native (per the specification) and is shown over the lock screen by
temporarily allowing `MainActivity` to show when locked. Audio never stops while the challenge is
open. A 3-second emergency dismiss is always available.

### ADR-011 · Opt-in weather from Open-Meteo (amends "no INTERNET permission")
The owner requested a home-screen clock widget with weather. Weather is off by default, uses
Open-Meteo (no key, no account), sends only rounded coordinates, and is the app's only network
use. Optional coarse device location was added on request, foreground-only.

### ADR-012 · Original weather icons
Google Weather's icon set is proprietary ("All icons are the property of Google") and cannot be
redistributed. RCB Wake's weather icons are original artwork generated by
`scripts/generate-weather-icons.py`.

### ADR-013 · Settings screen always in English
At the owner's request, Settings stays in English regardless of the chosen language, so the
language option can always be found.

### ADR-014 · PolyForm Noncommercial License 1.0.0
The owner wants the source public while reserving commercial use. PolyForm Noncommercial permits
use, study and modification for non-commercial purposes; commercial use needs the author's
permission. This makes RCB Wake *source-available* rather than OSI open source.

### ADR-015 · Bundled tones are synthesised
To avoid redistribution questions, alarm tones are generated from sine waves by
`scripts/generate-tones.py`.
